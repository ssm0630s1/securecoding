# 10주차 시큐어 코딩 작업 기록

범위는 R10-1~R10-6이다. 로그인 해시, 인증 및 권한 정책, 세션 정책은 이번 변경에 포함하지 않았다. 기존 API 주소와 정상 응답 형식을 유지했다.

| 요구사항 | 변경 내용 |
|---|---|
| R10-1 | 글, 댓글, 가입·로그인, 관리자 역할 변경, 첨부파일 저장 쿼리에서 SQL과 값을 분리했다. 값이 없는 고정 쿼리는 유지했다. |
| R10-2 | 게시글·댓글·관리자 요청의 번호와 업로드의 글 번호를 양의 정수로 검사한다. |
| R10-3 | 문자열 입력을 강제 변환하지 않고 실제 타입을 검사한다. |
| R10-4 | 제목 1~100자, 본문 1~5,000자, 댓글 1~500자, 이름 1~30자를 서버에서 검사한다. |
| R10-5 | 상세 본문은 정화한 HTML로 출력하고, 검색 제목의 텍스트 조각과 검색어는 JSX로 출력한다. 검색 강조에는 JSX의 `<mark>`를 쓴다. |
| R10-6 | 상세 본문에서 `b`, `i`, `u`, `br` 태그만 허용하며 모든 속성을 제거한다. |

## 외부 입력과 수정 이유

- 검색어는 `req.query.q`에서 받는다. 누락이나 빈 값은 전체 목록 검색으로 처리하고, 비문자열과 50자 초과는 400으로 거부한다. SQL의 `LIKE ?`에 검색 패턴을 별도 값으로 전달한다.
- 글·댓글 번호는 URL 파라미터 또는 업로드 폼에서 받는다. 데이터베이스를 조회하기 전에 형식을 검사하고, 쿼리의 자리표시자에 값으로 전달한다.
- 제목, 본문, 댓글, 이름 등은 요청 본문에서 받는다. 형식과 길이를 확인한 다음 바인딩한다. 길이 검증과 값 바인딩은 각각 다른 목적이다.
- 원본 본문 HTML을 그대로 렌더링하지 않고 DOMPurify의 허용 목록을 통과한 결과만 렌더링한다. 제목 및 댓글은 텍스트로 출력한다.
- 바인딩을 없애고 외부 값을 다시 SQL 문장에 이어 붙이면 값이 SQL 구조에 영향을 줄 수 있다. 본문 정화를 없애면 허용하지 않은 태그나 속성이 브라우저의 HTML 처리 단계에 들어갈 수 있다.

## 이 변경 사본에서 확인한 결과

- 서버 TypeScript 빌드와 클라이언트 프로덕션 빌드가 통과했다.
- 서버 라우트 자동 테스트는 DB 호출을 대체해 상태 코드, 길이 경계, 잘못된 타입 및 번호 거부, SQL과 값의 분리 여부를 확인했다. 서버 폴더에서 `npm run build` 후 `node --test tests/week10.test.cjs`로 재실행할 수 있다.
- 빌드한 클라이언트는 테스트용 API 응답으로 렌더링을 확인했다. 본문 태그 네 가지는 유지되고 속성은 제거됐으며, 검색 제목과 검색어는 텍스트로 표시되고 강조가 유지됐다. 댓글도 텍스트로 표시됐다.
- 이 변경 사본에서 실제 MySQL을 사용한 통합 테스트는 수행하지 않았다. 확인하지 않은 수정 전 요청·응답은 이 문서에 추가하지 않았다.
- AI를 사용해 수정과 자동 검증을 작성했다. 제출 전 실제 실행 결과와 본인이 확인한 내용을 추가한다.
